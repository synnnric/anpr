I. Overview
1.1 Connection Instructions
This document describes the HTTP interface interface specifications between third-party systems and the S300 system, covering two aspects:
direction
	illustrate
S300 → Third Party
	The S300 system proactively pushes the data reported by the S300 device to a third-party platform.
Third party → S300
	Third parties can implement process-driven operations and control of S300 devices by calling the S300 system interface.
1.2 Communication Specifications
Protocol : HTTP/HTTPS
Data format : JSON
Character encoding : UTF-8
Request method : POST / GET
Content-Type : application/json
1.3 General Response Format
All interfaces provided by the S300 side return a uniform format:
{  "code" : 200 ,  "message" : "Operation successful "  "data" : {} }
Fields
	type
	illustrate
code
	Integer
	Status codes: 200 indicates success, anything other than 200 indicates failure.
message
	String
	Prompt message
data
	Object
	The returned data and its specific structure are detailed in the respective interface descriptions.

3.1 Receive working status data
Interface Description : Receives S300 device operating status data sent by the S300 system.
property
	value
Request method
	POST
Request path
	Third-party custom OVERSEAS_WORK_STATUS_URL
Default configuration value
	http://127.0.0.1:8080/overseas/s300/work-status
The request body sent by the S300 system :
{ "cmdNo": 322, "channelNo": "CH001", "data": { "operatingState": 0 } }
Request field description :
Fields
	type
	illustrate
cmdNo
	Int
	Fixed value 322 , indicating working status data.
channelNo
	String
	Channel number
data
	Object
	Working status data
data.operatingState
	Int
	Running status: 0 = normal; see enumeration description for other values.
operatingState enumeration values :
value
	meaning
	Supplementary Explanation
0
	Ready
	The robotic arm and screen are all in a reset state.
1
	Under inspection
	Upon receiving the start-of-work instruction (corresponding to 2.1.1), the inspection begins.
2
	Resetting
	Upon receiving the work completion instruction (corresponding to 2.1.3) , the device begins to reset.
3
	Reset complete
	The equipment has been reset and vehicles can now pass.
4
	Emergency stop of equipment
	Upon receiving an emergency stop command (corresponding to 2.2.2), the equipment ceases operation.
5
	Equipment failure
	Equipment malfunction, unable to work
6
	Equipment self-testing
	The device performs a self-test to check if its status has returned to normal.
The third party needs to return :
{ "code": 200, "message": " success ", "data": {} }
The S300 system considers a 200 HTTP status code response as a successful reception, and the response body format is not mandatory.

3.7 Receive Video Recording Files
Description: Receives complete video recording data for the current inspection pushed by the s300 system. After receiving the “Complete Work” notification (/channel/http/leave), the s300 system saves the recordings from all six robotic arm cameras (covering the period from start time to end time) and pushes the file URLs to the third-party for archiving.
Property
	Value
Method
	POST
Path
	Third-party defined; configure as OVERSEAS_VIDEO_RECORD_URL
Default
	http://127.0.0.1:8080/overseas/s300/video-record
Trigger: After the third-party calls POST /channel/http/leave/{channelNo}, the s300 system finishes saving the recordings and actively pushes to this interface.

Notes: - After each inspection, exactly 6 recording files are pushed. If a camera recording fails, the corresponding url will be an empty string "". - File naming convention: {channelNo}_{code}_{startTime yyyyMMddHHmmss}.mp4. - The third-party should download and save the files promptly. The s300 system only retains recent recordings and does not guarantee long-term storage.
Third-party must return:
{ "code": 200, "message": " success ", "data": {} }
The s300 system considers the push successful when the HTTP response status code is 200. The response body format is not strictly required.

VI. Remarks
Protocol: http
Capture Process: Our robotic arm performs face capture and deduplication. A single robotic arm sends only one or two images, ensuring that the number of captured images pushed to the customer at one time is not too large. The customer will then actively call the interface to continue capturing images, and the robotic arm will restart the capture push.
VIP vehicles : Users can choose not to send start-of-work information and do not need to undergo S300 system verification.
